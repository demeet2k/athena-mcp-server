## Runtime command surface

Core registry operations:

- `athena_kc144_registry_status` returns the immutable archive identity, package member, declared counts, and lens inventory.
- `athena_kc144_registry_catalog` lists every embedded registry and verifies member presence.
- `athena_kc144_registry_query` performs bounded deterministic reads, including exact dotted-path filters such as `address.gid`.
- `athena_kc144_registry_verify` validates the carrier digest, reconstructs all members, parses every required body, and compares declared counts.

Topological lenses:

- `athena_kc144_registry_cross_search` performs bounded exact lexical retrieval across selected registries with a reproducible ranking law.
- `athena_kc144_registry_source_bundle` braids one exact `source_id` to all linked maths, graphs, coordinates, harnesses, skills, tools, source and dataset records.
- `athena_kc144_registry_cell_bundle` hydrates one immutable GID with its full cell address, hosted identities/counts, HOLDs, and exact host/semantic completion links.
- `athena_kc144_completion_frontier` projects the ready and blocked task frontier from an explicit set of completed task IDs over the full `TASK.000..TASK.125` dependency snapshot.

Resources expose status, catalog, manifest, verification and the default source-bound completion frontier under `athena://kc144/*`.

## Epistemic boundary

A successful pack verification certifies byte identity, safe reconstruction, member presence, JSON parseability and count agreement. Cross-search is lexical, not semantic authority. Source bundles use exact identity equality, not inferred sameness. Completion-frontier calculation is a pure projection over a source snapshot, not proof of live execution. None of these routes converts a proposal into evidence, infers causal truth from graph reachability, promotes authority, merges a pull request, or discharges an external CI/migration HOLD.
