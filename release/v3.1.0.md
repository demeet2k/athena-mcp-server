# ATHENA 3.1.0 — Deployment Control Plane

ATHENA 3.1 closes the gap between the 3.0 distributable organism and a securely hostable, observable, rollback-capable service.

## New runtime organs

- `DeploymentHubServer`: one canonical runtime root that composes DEPLOYMENT.1 above Collective V11 × KC144.
- `athena-mcp-http`: a bounded JSON-RPC-over-HTTP host with bearer authentication, body limits, graceful termination, and explicit transport boundaries.
- Four deployment tools, three deployment resources, and an activation-control prompt.
- Digest-only production image validation.
- Isolated-canary planning, single-writer cutover, bounded canary assessment, and rollback routing.

## Network and health surface

```text
POST /mcp
GET  /livez
GET  /readyz
GET  /healthz
GET  /metrics
```

The adapter does not claim MCP Streamable HTTP, SSE, or resumable-session semantics. Off-loopback RPC requires a bearer token. TLS is terminated by trusted external infrastructure.

## OCI and deployment distribution

The release workflow publishes a multi-platform `linux/amd64` + `linux/arm64` image to:

```text
ghcr.io/demeet2k/athena-mcp-server
```

The release attestation records the exact manifest digest. Tags are navigation aliases; Kubernetes and activation plans bind the digest.

The runtime image uses UID/GID 65532, a read-only root filesystem contract, all Linux capabilities dropped, no-new-privileges, an explicit state volume, and `/readyz` health checking.

## Persistent-state law

SQLite WAL remains single-writer:

```text
replicas = 1
strategy = Recreate
volume = ReadWriteOnce
old writer and new writer may not overlap on production state
```

Canaries use isolated fresh or snapshot-cloned state. Active-active operation requires a separately implemented transactional backend.

## Activation boundary

This release publishes the package, OCI image, deployment templates, attestations and checksums. It does not inject production secrets, create a host, apply Kubernetes resources, move traffic, mutate DNS, mount a production database, or establish empirical/Y1 truth.
